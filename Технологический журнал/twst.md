


Это твой **Полный справочник (Cheat Sheet) по всем событиям Технологического журнала 1С**. 

Я оформил его так, как это должно лежать в голове у Senior-администратора: с расшифровкой аббревиатур, реальным смыслом и уровнем опасности для сервера (можно ли держать включенным или это убьет диски).

---

### 🗄️ ГРУППА 1: Работа с Базами Данных (СУБД)
*Всё, что связано с запросами, SQL и данными.*

*   **`DBPOSTGRS`** (PostgreSQL) 🚨 **[Мастхэв]**
    *   **Что это:** Исполнение SQL-запроса к базе PostgreSQL.
    *   **Зачем админу:** Главный инструмент поиска тормозов. Содержит текст SQL (`Sql`) и план запроса (`plansqltext`). **Включать всегда, но строго с фильтром по длительности** (например, `Duration > 3 сек`).
*   **`SDBL`** (Schema Data Base Language) 🔍
    *   **Что это:** Исполнение запросов на внутреннем «движке» 1С (до того, как они переведены в SQL).
    *   **Зачем админу:** Если SQL-запрос выглядит как нечитаемая каша, программисты просят лог `SDBL`, чтобы понять логику платформы. Включать только точечно.
*   **`QERR`** (Query Error) ⚠️
    *   **Что это:** Ошибки компиляции запросов или блокировки по правам доступа (RLS).
    *   **Зачем админу:** Если у пользователя пропадают документы из списков из-за хитрых настроек прав доступа, `QERR` покажет причину. Включать при расследовании багов с правами.
*   **`EDS`** (External Data Sources) 🌐
    *   **Что это:** Работа с Внешними источниками данных (подключение 1С напрямую к MySQL, Oracle и т.д.).
    *   **Зачем админу:** Ловить тормоза при интеграции 1С с сайтами или внешними системами.
*   *Мусорные для тебя события (т.к. у тебя Linux+Postgres):* **`DBMSSQL`** (MS SQL), **`DBORACLE`** (Oracle), **`DB2`** (IBM DB2), **`DBV8DBENG`** (Файловая база 1С).

### 💥 ГРУППА 2: Аварии, Ошибки и Процессы ОС
*Твоя скорая помощь. Эти логи должны собираться 24/7.*

*   **`EXCP`** (Exception) 🚨 **[Мастхэв]**
    *   **Что это:** Исключительная ситуация (ошибка). Любая красная табличка у пользователя (деление на ноль, нехватка памяти, разрыв сети).
    *   **Зачем админу:** Фиксирует факт аварии. Обязательно к сбору.
*   **`EXCPCNTX`** (Exception Context) 🚨 **[Мастхэв]**
    *   **Что это:** Контекст ошибки. Идет всегда в паре с `EXCP`.
    *   **Зачем админу:** Показывает стек вызова (строку кода 1С), которая привела к падению. Без него ошибка `EXCP` слепа.
*   **`PROC`** (Process) 🚨 **[Мастхэв]**
    *   **Что это:** Старт, штатное завершение или аварийное падение (`Abnormal termination`) процессов `ragent`, `rmngr`, `rphost`.
    *   **Зачем админу:** Отслеживать, не убивает ли Linux рабочие процессы (например, OOM Killer'ом).
*   **`SYSTEM`** ☠️ **[ОПАСНО]**
    *   **Что это:** Внутренние низкоуровневые логи (C++) разработчиков платформы 1С.
    *   **Зачем админу:** **НИКОГДА НЕ ВКЛЮЧАТЬ САМОСТОЯТЕЛЬНО.** Включается только по прямой указке техподдержки фирмы 1С. Убьет диски сервера гигабайтами мусора за минуты.

### 🔒 ГРУППА 3: Параллельная работа и Блокировки
*Главный инструмент для администрирования ERP-систем.*

*   **`TTIMEOUT`** (Transaction Timeout) 🚨 **[Мастхэв]**
    *   **Что это:** Превышение времени ожидания управляемой блокировки (обычно 20 секунд).
    *   **Зачем админу:** Показывает, **КТО** ждал и **КОГО** не дождался. Помогает найти сеансы, блокирующие работу целых отделов.
*   **`TDEADLOCK`** (Transaction Deadlock) 🚨 **[Мастхэв]**
    *   **Что это:** Взаимоблокировка (процесс А ждет Б, процесс Б ждет А). Платформа «убивает» одного из них.
    *   **Зачем админу:** Это всегда архитектурная ошибка кода. Ловим и отдаем программистам на исправление.
*   **`TLOCK`** (Transaction Lock) 🗑️
    *   **Что это:** Сам факт установки любой управляемой блокировки.
    *   **Зачем админу:** Включать только на тесте по просьбе разработчиков. На боевом сервере создаст миллионы строк логов и остановит работу.

### 📞 ГРУППА 4: Клиент-Сервер и Вызовы
*Поиск тормозов интерфейса и сети.*

*   **`SCALL`** (Server Call) 🚨 **[Мастхэв]**
    *   **Что это:** Исходящий вызов (обычно Тонкий клиент звонит на Сервер).
    *   **Зачем админу:** Покажет, какая именно кнопка заставила интерфейс пользователя «повесить» 1С. Включать на постоянку **только с фильтром по времени** (`Duration > 3 сек`).
*   **`CALL`** (Входящий вызов) 🔍
    *   **Что это:** Момент, когда сервер 1С «снял трубку».
    *   **Зачем админу:** Сравнивая время `SCALL` и `CALL`, можно доказать сетевикам, что тормозит не сервер, а VPN/Wi-Fi пользователя.
*   **`SCOM`** (Server Context) 📉
    *   **Что это:** Создание или удаление контекста на сервере.
    *   **Зачем админу:** Помогает понять, почему при открытии некоторых форм съедаются сотни мегабайт ОЗУ (какие данные гоняются между клиентом и сервером).
*   **`SESN`** (Session) 🛡️
    *   **Что это:** Начало и окончание сеанса 1С.
    *   **Зачем админу:** Аудит. Узнать, во сколько пользователь пришел на работу и с какого IP-адреса.

### 🧠 ГРУППА 5: Утечки памяти и RAM

*   **`LEAKS`** (Утечки) 🛠️
    *   **Что это:** Поиск «забытых» в оперативной памяти объектов 1С.
    *   **Зачем админу:** Включать точечно (ночью или на тесте), когда процесс `rphost` раздувается и не возвращает память ОС Linux.
*   **`MEM`** (Memory) ☠️ **[ОПАСНО]**
    *   **Что это:** Логирует **любое** выделение оперативной памяти процессами.
    *   **Зачем админу:** Категорически запрещено включать на проде! Повесит процессор системными прерываниями. Используется только разработчиками.

### 🏢 ГРУППА 6: Кластер, Сеть и Администрирование

*   **`ADMIN`** (Admin) 🛡️ **[Мастхэв]**
    *   **Что это:** Любые управляющие воздействия на кластер.
    *   **Зачем админу:** Контроль за коллегами. Кто удалил базу, кто скинул сеанс директора, кто поменял настройки кластера.
*   **`CONN`** (Connection) 🌐
    *   **Что это:** Установка или разрыв TCP-соединений.
    *   **Зачем админу:** Расследование жалоб «Меня выкинуло из 1С». Показывает, кто инициатор разрыва сети.
*   **`CLSTR`** (Cluster) ⚙️
    *   **Что это:** Внутренние операции кластера (синхронизация менеджеров).
    *   **Зачем админу:** Включать при проблемах с отказоустойчивостью или когда два сервера в кластере «теряют» друг друга.
*   **`SRVC`** (Services) ⚙️
    *   **Что это:** Запуск/остановка внутренних микросервисов 1С (например, сервиса лицензирования).
*   **`ATTN`** (Attention) 🗑️
    *   **Что это:** Служебные записи мониторинга состояния. (Технический шум).

### 🧰 ГРУППА 7: Специфические механизмы

*   **`HASP`** 🔑
    *   **Что это:** Обращения к аппаратным ключам защиты.
    *   **Зачем админу:** Если 1С запускается по 2-3 минуты. Лог покажет, по каким IP-адресам программа ищет ключи и ловит таймауты (лечится правкой `nethasp.ini`).
*   **`VRSCACHE`, `VRSREQUEST`, `VRSRESPONSE`** (Virtual Resource System) 🖼️
    *   **Что это:** Работа Тонкого/Веб клиента с картинками, формами и кэшем интерфейса.
    *   **Зачем админу:** Включать, если интерфейс отрисовывается долго, но сам сервер не нагружен (проблема с кэшем на ПК юзера или узкий интернет-канал).
*   **`FTEXTCheck`, `FTEXTUpd`** (Full Text Search) 🗂️
    *   **Что это:** Проверка и обновление индексов Полнотекстового поиска.
    *   **Зачем админу:** Ловить фоновые задания, которые «шерудят» диски Linux (высокий I/O), перестраивая гигабайты индексов днем.
*   **`InputByString`** ⌨️
    *   **Что это:** Ввод по строке (когда юзер печатает буквы, а 1С предлагает варианты в выпадающем списке).
    *   **Зачем админу:** Если 1С зависает на 5 секунд при попытке выбрать контрагента из списка.
*   **`MAILPARSEERR`** 📧
    *   **Что это:** Ошибка разбора почтового сообщения.
    *   **Зачем админу:** Если 1С сама читает почту (e-mail) и ломается на кривой кодировке письма.
*   **`CONFLOADFROMFILES`** 💻
    *   **Что это:** Операции загрузки конфигурации из XML-исходников.
    *   **Зачем админу:** Для DevOps-процессов при интеграции 1С с Git и СППР.
